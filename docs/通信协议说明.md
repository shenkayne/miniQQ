# miniQQ 客户端通信协议说明

本项目采用 **C/S 架构**，通信分为两条通道：

- **TCP（命令/业务请求）**：客户端与服务端之间使用 `Socket` + `DataInputStream/DataOutputStream`。
  - 用途：登录、注册、查询好友/用户、添加/删除好友、找回密码、退出等。
- **UDP（聊天消息/抖动/记录）**：服务端使用 `DatagramSocket` 监听固定端口接收消息，再转发给目标客户端。
  - 用途：聊天文本、窗口抖动、聊天记录请求/返回、会话建立通知等。

---

## 1. TCP 协议（DataInputStream/DataOutputStream）

### 1.1 总体格式

- 客户端每次发起一个 TCP 连接（`new Socket(serverip, servertcp.port)`）。
- 第一段数据为 **命令字符串**（`out.writeUTF(cmd)`）。
- 后续字段按顺序写入（`writeUTF/writeInt`）。
- 服务端 `QQServer/src/com/controller/Server.java` 的 `run()` 里：
  - `String str = in.readUTF();`
  - 根据 `str` 分发到不同方法。

服务端命令分发位置：`QQServer/src/com/controller/Server.java`（`run()` 循环，类似 switch）。

---

### 1.2 login（登录）

客户端发送（见 `QQClient/src/com/controller/ClientToServer.java:sendLoginInfoToServer`）：

1) `writeUTF("login")`
2) `writeUTF(qq)`
3) `writeUTF(pwd)`
4) `writeUTF(clientReceivePort)`  客户端用于接收 UDP/消息的端口（由 `ReceivePort` 生成）
5) `writeUTF(clientIP)`           客户端 IP（本机通常是 127.0.0.1 或局域网 IP）

服务端处理（见 `QQServer/src/com/controller/Server.java:login`）：

- 校验 `UserInfo` 账号密码
- 检查 `Login` 表避免重复登录

服务端返回：

- `writeUTF("loginSuccess")` / `writeUTF("loginFail")` / `writeUTF("reLogin")`

若成功（loginSuccess），继续返回：

- 当前用户信息（顺序固定）：
  1) qq（UTF）
  2) pwd（UTF）
  3) sign（UTF）
  4) photoId（int）
  5) nickname（UTF）
  6) sex（UTF）
  7) birthday（UTF）
  8) telephone（UTF）
  9) email（UTF）
  10) address（UTF）

- 好友数量：`writeInt(friendCount)`
- 然后循环 friendCount 次，返回每个好友：
  - fqq（UTF）
  - sign（UTF）
  - photoId（int）
  - nickname（UTF）
  - sex（UTF）
  - birthday（UTF）
  - telephone（UTF）
  - email（UTF）
  - address（UTF）
  - subgroupName（UTF）
  - 在线状态：`"onLine"` 或 `"NotonLine"`
    - 若 onLine：额外返回 lip（UTF）、lport（int）

---

### 1.3 registerNewUser（注册）

客户端发送：

1) `writeUTF("registerNewUser")`
2) pwd（UTF）
3) sign（UTF）
4) photoID（int）
5) nickname（UTF）
6) sex（UTF）
7) birthday（UTF，yyyy-MM-dd）
8) telephone（UTF）
9) email（UTF）
10) address（UTF）
11) question1No（int）
12) answer1（UTF）
13) question2No（int）
14) answer2（UTF）
15) question3No（int）
16) answer3（UTF）

服务端返回：
- `writeInt(newqq)`（新注册的 QQ 号）

---

### 1.4 queryFriend（刷新好友列表）

客户端发送：
- `writeUTF("queryFriend")`

服务端响应：
- `writeInt(friendCount)` + 循环返回好友信息（同 loginSuccess 的好友返回结构）。

---

### 1.5 queryUser / queryUser1（查找用户）

- `queryUser`：按 qq 精确查
  - 客户端：`writeUTF("queryUser")` + `writeUTF(qq)`
  - 服务端：返回该用户完整信息（字段顺序同 loginSuccess 当前用户信息）

- `queryUser1`：按 qq 或 nickname 模糊（或）
  - 客户端：`writeUTF("queryUser1")` + `writeUTF(qq)` + `writeUTF(nickname)`
  - 服务端：先回 `ExistUser` 或 `NotExistUser`
    - ExistUser 时返回：qq（UTF）/sign（UTF）/photoId（int）/nickName（UTF）

---

### 1.6 addFriend（添加好友）

客户端发送：

1) `writeUTF("addFriend")`
2) fqq（int）  被添加好友 qq
3) subno（int）分组编号
4) qq（int）   自己 qq

服务端返回：
- `writeUTF("flushFriend")`（提示客户端刷新好友列表）

---

### 1.7 deleteFriend（删除好友）

客户端发送：

1) `writeUTF("deleteFriend")`
2) fqq（int）
3) qq（int）

---

### 1.8 getPwd（找回密码）

客户端发送：

1) `writeUTF("getPwd")`
2) `writeUTF(qq)`

服务端返回：

- 3 组密保：每组为 question（int）+ answer（UTF）
- 最后返回密码：pwd（UTF）

---

### 1.9 logout / end

- `logout`：退出登录（服务端会删除 Login 表记录）
- `end`：关闭连接

---

## 2. UDP 协议（DatagramSocket + 对象序列化）

### 2.1 数据格式

UDP 通道发送的是 **序列化后的 Java 对象**：

- `com.common.Message`
- 有时也会发送 `Hashtable`（例如聊天记录 record）

服务端接收线程：`QQServer/src/com/controller/ServerToClientThread.java`
- 监听端口：`receivePORT`（默认从 `QQServer/src/ServerInfo.properties` 读取，常见为 8888）
- 接收到 datagram 后：`Message message = (Message) ByteToObject(receivePacket.getData())`

### 2.2 消息类型（Message.infoType）

在服务端代码中出现的类型包括：

- `TXT`：文本消息
  - 服务端会先 `Dml.insert(message)` 写入数据库，再 `sendData(message)` 转发
- `Shake`：窗口抖动
- `Record`：请求/返回聊天记录
- `Notice`：建立会话/端口协商通知（第一次聊天会交换端口）

> 注意：UDP 通道里存在“第一次会话需要协商端口”的逻辑（`LinkPort.isfirst` + `TwoPortMsg`）。

---

## 3. 协议特点与注意事项

1) **强顺序依赖**：TCP 部分靠字段顺序读写，客户端/服务端必须严格一致。
2) **字符串命令分发**：服务端通过 `in.readUTF()` 读命令字符串判断业务。
3) **混合 TCP + UDP**：
   - TCP 管理与查询（可靠）
   - UDP 传聊天消息（不保证可靠/顺序）
4) **字符集**：聊天入库需确保数据库表字段为 `utf8mb4`，否则中文会写入失败导致收不到消息。
